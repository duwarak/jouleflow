The idea

Electricity isn't equally dirty all day. The same batch job run at 7pm in a coal-heavy grid can emit ten times the CO₂ of the same job run at 9am where the sun is up.

Most JVM workloads don't care exactly when they run — they care about a deadline. JouleFlow turns that slack into carbon savings, and writes down every decision it made and why.

The rule that matters

An estimate is never shown as a measurement

Intel RAPL gives real hardware energy counters — but it's masked in most containers and cloud VMs since the PLATYPUS side-channel attacks (CVE‑2020‑8694/8695). Rather than quietly guessing, JouleFlow tags every single number with where it came from, and carries that tag all the way to the ledger and this page.

MEASURED

Read from real Intel RAPL hardware counters. Only happens on bare-metal Linux with an accessible powercap driver.

ESTIMATED

Derived from JVM CPU time × an assumed watts-per-core constant. A proxy — it ignores DRAM, GPU and idle draw. Labelled everywhere.

UNAVAILABLE

No figure could be produced at all. Better than a number nobody can trust.

Under the hood

How one task flows through

1

Profile it for real

JfrTaskProfiler wraps the task in a live jdk.jfr.Recording, writes a .jfr file, then parses it back for event count and GC pause time.

2

Attribute the energy, honestly

RaplEnergyReader is tried first; if the hardware counters aren't readable it falls back to FallbackEnergyReader and stamps every reading ESTIMATED.

3

Ask the grid

CarbonIntensityProvider supplies current and forecast gCO₂/kWh — illustrative sample curves, or the live Electricity Maps API with a key.

4

Decide, conservatively

Scheduler compares the best deferred hour against the cleanest candidate region, and only moves the job if the win clears the threshold.

5

Write it down

Ledger records energy, source tag, region, intensity, emissions, the avoided baseline, and the rationale into SQLite — auditable after the fact.

Read this honestly. The playground above uses illustrative grid curves, not a live feed. The recorded run's energy figures are CPU-time estimates, not hardware measurements. Absolute emissions are small because the demo workloads are short — the point is the mechanism and the provenance, not the milligrams.
